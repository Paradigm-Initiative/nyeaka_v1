## Project scope (locked decisions)

- **Africa-wide by design.** Nyeaka is not Nigeria-only. Nigeria, Ghana, Kenya, Cameroon, Senegal, Zambia and Zimbabwe are enabled today; an admin switches any other country on once its legal read is done (see "Enabled countries" below). Nothing in the schema, copy, phone handling or verification flow may assume Nigerian documents, phone numbers or law.
- **Same-country matching only (v1).** Handoff is in person, so listings, requests and offers only pair people in the same country. Cross-border matching stays off until decided otherwise.
- **Country is required.** `User.countryCode` (ISO 3166-1 alpha-2) is set at signup. Browse defaults to the user's own country.
- **Phone numbers** are validated and stored as E.164 by `libphonenumber-js` (`lib/phone.ts`), with no per-country data of our own. The UI uses `react-phone-number-input`. SMS OTP is per-country and only where delivery is confirmed; otherwise rely on email verification.
- **KYC is manual review for now.** Automated verification providers are deferred, per country. ID numbers are never stored in plain text, only as an HMAC (`docNumberHash`). ID images live in a private R2 bucket, are viewed only through short-lived signed URLs, and are deleted 30 days after the decision.
- **Gating.** `User.idVerificationStatus === VERIFIED` is required to create listings, requests and offers, enforced server-side. `idVerificationStatus` is the single source of truth (there is no `idVerified` boolean).
- **Roles.** Keep the existing `Role` enum; only `ADMIN` is special. Enforce it in the proxy/middleware and again inside every admin server action.
- **Deployment.** Vercel now, then Docker on a Coolify server. Scheduled jobs are protected route handlers (`Authorization: Bearer $CRON_SECRET`), triggered by Vercel Cron today and a Coolify scheduled task later. Do not depend on Cloudflare Workers or Cron Triggers.
- **i18n is live (next-intl; `en`, `fr`, `pt`); never hard-code English.** All user-facing copy (forms, errors, emails, notices, legal pages) goes in `messages/*.json` and is read with `useTranslations`/`getTranslations`, in all three catalogues. Locale is a cookie (`i18n/`), with no URL prefix. Services should throw a translation key or a message mapped in `lib/error-keys.ts`, not new unmapped English sentences. Country names come from `Intl.DisplayNames`, never stored. Emails to users are written in `user.locale` (copy under `emails` in the catalogues, built by `lib/email-i18n.ts`); admin emails stay English. Use `Intl` for dates and numbers, and don't assume English text length in layouts. The admin area is English only for now, so it needs no translation.
- **Enabled countries live in the database, not in code.** The `EnabledCountry` table holds only the enabled ones; an admin switches a country on or off at `/admin/countries` (no deploy). Read it through `lib/enabled-countries.ts` (async, cached about a minute per instance). `lib/countries.ts` only lists which countries exist (the 54 African ones) plus optional ID-document defaults. Enabling a country needs no other config, since phone rules come from `libphonenumber-js`. The legal read before enabling is a real-world step, not code.
